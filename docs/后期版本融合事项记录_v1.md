# 后期版本融合事项记录

> 版本：v1（内容递增规则见文末「版本递增说明」）
> 目的：记录每次「源项目(OpenMinis) → 本 fork(deepseek-ai / 龙虾Ai)」融合过程中踩过的坑与恢复手法，防止后续融合版本时重复踩坑。历史上已发生过至少一次同样的覆盖事故，故立此档。

---

## 一、融合方向（铁律，不可搞反）

| 角色 | 仓库 | 说明 |
|---|---|---|
| **源 (source)** | `_work_src` = OpenMinis | 提供要合入的新功能 |
| **目标 (fork)** | `_work_fork` = deepseek-ai / 龙虾Ai | 推送 `github.com/hf805864818/deepseek-ai`，包名 `com.openminis.app` |

- 方向：**source → fork**，把 OpenMinis 的新代码合进 fork。
- fork 必须保留的独有资产：DeepMode 并行、Google Drive 同步、LocalSync、EnvProfile、定时任务、OtherSync、UpdateChecker、FastMode、**品牌（图标 / 版本号 / 应用名 LobsterAI / vbox-ai 链接）**、CI。
- 移除 fork 的 `task_dispatch`，保留 source 的 `subagent_task`。

---

## 二、三向对比审计法（每次融合必做）

融合完成后，用 fork 的**原始提交**作为基准做三方对比，而不是只 diff source vs fork：

```
基准 A = fork 首次提交 d921a0a（融合前 fork 原始状态）
基准 B = 当前 HEAD（融合后）
基准 C = source 当前 HEAD
```

对 A 中每个文件按其内容 hash 分类：

| 分类 | 判定 | 含义 |
|---|---|---|
| 本就相同 | A==C | 共享基底，无损失 |
| 保留 | A==B | fork 内容未动 |
| **被覆盖(真损失)** | A!=C 且 B==C | fork 特有内容被 source 顶掉 |
| 三方合并 | A!=B!=C | 双方内容都有，需人工核对 |
| 被删除 | 不在 B | 文件整个消失 |

**结论实测（2026 融合）**：1978 个基准文件里，609 个被 source 覆盖，其中 44 个是品牌资产、29 个含 fork 特有功能代码。

## 三、已知坑点清单

### 坑 1：品牌资产被 source 整包覆盖（图标 / 版本号 / 品牌链接）
- **图标**：Android `res/mipmap-*` 的 `ic_launcher*.png` 被 source 的图标替换（字节级不同，size 都变了）。
- **iOS 图标**：`Assets.xcassets/AppIcon.appiconset`（含 Tinted/Dark/full 系列）+ `Resources/AlternateIcons/*` + `Launch Screen.storyboard` 被替换。
- **版本号**：`src/ios/Minis.xcodeproj/project.pbxproj` 的 `MARKETING_VERSION` 从 `1.0.236` 被重置为低位，随后 CI 的 `scripts/increment-version.sh` 从 `1.0.1` 一路自增 → 出现"版本倒退"假象。
- **品牌链接**：iOS `AboutView / AddProviderView / SkillsManagementView / SettingsSheet`、Android `AboutScreen / MinisSkillsBrowserScreen` 里的 GitHub/隐私/Telegram/邮件链接全部变回 `openminis.github.io` / `OpenMinis` / `dev@openminis.app`。

**恢复手法**：
1. 图标/版本：`git checkout d921a0a -- <资产路径>` 整套捞回。
2. 版本号：手动把 `MARKETING_VERSION`、`CURRENT_PROJECT_VERSION`、gradle `versionName/versionCode` 一起对齐到目标值（本次 1.0.237）。
3. 品牌链接：**不要整文件回滚**（会丢 source 新功能），只把 URL/文案字符串换回 fork 的。

### 坑 2：fork 独有功能入口在融合后「孤儿化」
- 屏幕文件都在（如 `SubAgentsScreen.kt`、`NetworkSettingsScreen.kt`、`AgentToolsSettingsScreen.kt`、`ScheduledTasksSettingsView.swift`、`OtherSyncSettingsView.swift`），但 `AppNavigation.kt` 没注册 `composable(Routes.X)`、`SettingsScreen`/`SettingsSheet` 没画入口行 → 编译进去但点不到。
- iOS `SettingsSheet.swift` 被 source 版整体替换，fork 的 DeepMode/SpecMode 开关、Scheduled Tasks、Other Sync 入口全部丢失。

**恢复手法**：逐条补入口行 + 路由 composable + 路由常量，保留 fork 已有入口（DeepMode/OtherSync）。

### 坑 3：iOS DeepMode 主开关「只读、无 UI」
- 引擎全套都在（`DeepModeStore` / `SpecGate` / `VerifyGate` / `WorkflowState`），但 `UserDefaults` key `deepMode.enabled` / `deepMode.specMode` **只有读取、没有任何写入 UI** → DeepMode 永远关着。
- 恢复：在 `SettingsSheet` 加 `@AppStorage("deepMode.enabled")` / `@AppStorage("deepMode.specMode")` 两个 Toggle，翻转时发 `deepModeDidChange` 通知让存活 VM 硬复位。

### 坑 4：`subagent_task` 开关在老用户设备上被迁移成 OFF
- iOS `AgentToolSwitch.migrateLegacyIfNeeded()` 会把旧 `agent.tools.enabled`（或 HelperSettings 旧 key）为 OFF 的老用户一次性迁移成 `agent.tools.agents.enabled = false`。
- 结果：**全新安装默认开，升级安装可能是关的** → 模型收不到 `subagent_task` 工具，子任务派遣完全不触发。
- 排查信号：让模型「列出所有工具」，若没有 `subagent_task`，就是开关被关。
- 修复：用户到「设置 → Sub Agents」打开总开关即可。

### 坑 5：fork 旧 composer 被整包删除，自定义 UI 修复跟着丢
- 融合提交 `174a012` 删除了 fork 的旧 composer 5 个拆分文件（`AIChatView+InputBar/Auxiliary/Sheets/Toolbar/Types.swift` + 旧 `ChatInputBar` 主体），换成 source 的新 `AIChatView/` 拆分 composer。
- fork 对旧 composer 做的任何自定义修复（如按键阴影）**跟着旧文件一起消失**，且新 composer 结构不同，只能**重新实现**不能拷贝。

### 坑 6：fork git 历史被重写，原始历史不可见
- fork 仓库只有 70 个融合期提交，原始开发历史被 squash/重写成首个提交 `d921a0a`。
- 后果：无法用 `git log --grep` 找到融合前的具体 fix 提交，只能靠 `d921a0a` 的**文件内容**反查。
- 三向对比基准务必固定为 `d921a0a`。

### 坑 7：CI 版本自增与 pbxproj 覆盖叠加
- `build-and-release.yml` 的 `prepare` 每次 push 都跑 `increment-version.sh` 自增并 push `[skip ci]` 提交。
- 若 pbxproj 的 `MARKETING_VERSION` 在融合中被覆盖成低位，CI 会从低位持续 +1，版本号持续「倒退」。
- push 网络问题：直连 `github.com` + `http.version=HTTP/1.1` + `lowSpeedLimit/lowSpeedTime` + 重试循环（代理节点不支持 push）。

## 四、恢复手册（标准流程）

1. `git ls-tree -r d921a0a` / `git ls-tree -r HEAD` / source 侧 `git ls-tree -r HEAD` 导出三份树。
2. 按 hash 三向对比，产出「被覆盖 / 被删除 / 三方合并」清单。
3. **资产类**（图标 / storyboard / 图片）：`git checkout d921a0a -- <路径>` 整套恢复。
4. **字符串类**（品牌 URL / 文案）：保留 source 新代码，仅替换品牌字符串。
5. **功能代码类**（FastMode / ScheduledTask / DeepMode 碎片）：逐文件 diff `d921a0a` vs `HEAD`，把 fork 特有的逻辑块重新缝回。
6. 版本号：对齐 pbxproj + gradle + VERSION.txt，定一个递增目标。
7. 提交前用 `git status` 确认变更都在预期内；提交信息注明「恢复 fork 品牌/功能」。
